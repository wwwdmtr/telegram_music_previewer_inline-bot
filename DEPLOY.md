# Деплой на VPS через Dokploy

Ваш план верный: пуш в GitHub → приложение в Dokploy → сборка по Dockerfile →
автодеплой на пуш в ветку. Ниже — что конкретно выставить и на чём обычно
спотыкаются.

## 1. Тип приложения

Берите **Application** с билдером **Dockerfile**, а не Docker Compose.

Причина: в продакшене Redis не нужен (одна реплика — кэш в памяти процесса даёт
тот же hit-rate), а значит поднимать нечего, кроме самого бота. `Dockerfile`
лежит в корне репозитория, `CMD` уже прописан — Dokploy соберёт и запустит без
дополнительных настроек.

Compose-режим понадобится только если захотите Redis: тогда указывайте
`docker-compose.yml` + `docker-compose.redis.yml`.

## 2. Домен и порты — не нужны

Бот работает через long polling: он сам стучится в Telegram, наружу ничего не
слушает. Поэтому:

- домен **не добавляйте**;
- порты **не публикуйте**;
- HTTP health check не настраивайте — отвечать на него нечем.

Dokploy ориентирован на веб-приложения и может подсказывать добавить домен.
Для воркера это просто пропускается.

## 3. Переменные окружения

`.env` в репозиторий не попадает (он в `.gitignore` — там ваш токен). Все
настройки задаются в разделе Environment у приложения в Dokploy. Бот читает их
напрямую из окружения, файл не требуется — проверено запуском контейнера без
`.env`.

Минимум, который нужно вписать:

```
BOT_TOKEN=<токен от @BotFather>
```

Всё остальное имеет рабочие значения по умолчанию. Что стоит задать осознанно:

```
ADMIN_IDS=<ваш telegram id>     # чтобы работала /stats
CACHE_BACKEND=memory            # одна реплика — Redis не нужен
LOG_LEVEL=INFO
```

Полный список с комментариями — в `.env.example`.

## 4. Автодеплой

Подключите репозиторий и включите Auto Deploy на нужной ветке. Dokploy
создаст webhook, GitHub будет дёргать его на каждый пуш. Дальше пуш в ветку =
пересборка образа и перезапуск контейнера.

## 5. Главная грабля: два polling-инстанса на один токен

Telegram разрешает только **один** `getUpdates` на токен. Второй получает:

```
TelegramConflictError: terminated by other getUpdates request
```

Отсюда два следствия:

1. **Остановите локальный контейнер перед деплоем** — иначе он и VPS будут
   драться за апдейты, а бот будет отвечать через раз:
   ```bash
   docker compose down
   ```
2. **Деплой должен пересоздавать контейнер, а не катить rolling-обновление.**
   Если Dokploy на секунду поднимет новый контейнер рядом со старым, они
   конфликтнут. Для воркера нужен режим «остановить и заменить»
   (recreate / stop-first), а не zero-downtime. Само по себе это не смертельно:
   старый контейнер умрёт, новый подхватит polling — но в логах будут
   `TelegramConflictError`, и это нормально только в момент деплоя.

## 6. Настройка бота в @BotFather

Делается один раз и не зависит от хостинга:

- `/setinline` — **обязательно**, иначе инлайн-режим не работает вообще.
  Placeholder: `исполнитель и название`.
- `/setinlinefeedback` — опционально, включите (лучше 10%, не 100%), если нужна
  метрика «сколько показов превратилось в отправку».

Если инлайн не включён, бот при старте напишет в логи предупреждение.

## 7. Проверка после деплоя

В логах приложения должно быть:

```
INFO music_bot: cache: in-process (max 5000 entries)
INFO music_bot: providers: deezer, itunes
INFO music_bot: throttle: inline 2.0/s burst 10, messages 0.5/s burst 5
INFO music_bot: starting as @ваш_бот (id=...)
INFO aiogram.dispatcher: Start polling
```

Если вместо этого:

| В логах | Причина |
|---|---|
| `Ошибка конфигурации: bot_token: Field required` | Не задан `BOT_TOKEN` в Environment |
| `не похоже на токен от @BotFather` | В токен попал лишний символ или кавычки |
| `Telegram отверг токен` | Токен по форме верный, но Telegram его не принял |
| `TelegramConflictError` | Где-то ещё работает второй инстанс с этим токеном |
| `inline mode is OFF` | Не выполнен `/setinline` |

Дальше наберите в любом чате `@ваш_бот creep` — в логах появится
`inline q='creep' offset=0 -> N tracks (source=deezer)`.

## 8. Ресурсы

- Образ ~250 МБ, сборка на слабом VPS — пара минут.
- Контейнер в работе: ~70–90 МБ RSS.
- Логи ротируются настройками Docker в compose; для Application-режима лимит
  задаётся в Dokploy, иначе на долгой работе они растут.

## Если репозиторий монорепо

Когда `music_inline_bot` лежит внуть общего репозитория с другими ботами,
укажите в Dokploy базовый каталог сборки (Build Path / Base Directory)
`music_inline_bot` — тогда `Dockerfile` найдётся, а контекст сборки будет
правильным.
